## 1. Trạng thái tool đã xác nhận

### Đổi kiến trúc tool (07/09/2026) — 1 tool duy nhất `SAP` thay vì bộ tool rời
- `GUI_TBD_DEV100` expose 1 tool `SAP` với `action`/`target`/`params`; không giả định kiến trúc qua tên server.
- `action="read", target="FUGR <name>"` chỉ trả metadata; đọc include phải dùng `INCL <include_name>`.
- `action="search", target="<pattern>*"` trả `Type` và `URI` đúng; dùng để lấy include/function group đúng trước khi `read`/`grep`.
- `action="grep", params={"package_name": ...}` không quét include của FUGR; cần gọi theo `object_url` cụ thể.
- `action="query", target="SQL"` là datapreview freestyle, có cú pháp kén; `JOIN`/`FOR ALL ENTRIES` thường không hỗ trợ.

### Bug đã xác nhận về include `PROG/I`
**[CONFIRMED]** Không có cách ghi source vào object `PROG/I` qua bất kỳ tool nào trên nhiều môi trường GUI: `CreateObject(PROG/I)` tạo shell rỗng nhưng mọi thao tác ghi sau đó đều fail với lỗi `resolving package for /sap/bc/adt/programs: package metadata not found`.
- Nền tảng: helper resolve-package phía server chỉ nhận dạng `.../programs/programs/<name>` nhưng không nhận diện `.../programs/includes/<name>`.
- Cách né: gộp TOP + F01 vào 1 `PROG/P` duy nhất hoặc dùng `EditSource` trực tiếp lên URL include trên một hệ đã xác nhận, `syntax_check=false`, `transport=<TR>`.
- Dấu hiệu đã kiểm tra lại: `LockObject` + `UpdateSource`, `EditSource`, `WriteProgram`, `WriteSource` đều fail với cùng pattern.
- **Ngoại lệ `GUI_S19_DEV100`:** ghi include chạy được — xem mục `GUI_S19_DEV100` bên dưới.

### `Activate`/`CreateAndActivateProgram` không đáng tin cậy hoàn toàn
**[CONFIRMED]** `success: true, messages: []` chưa phải là xác nhận thực thi thành công; nhiều lần chương trình thực sự còn inactive hoặc có lỗi cú pháp thật sau khi activate.
- Kênh đáng tin cậy nhất: `EditSource` với `syntax_check=true` trên URL object thật, hoặc user mở SE38/Ctrl+F2 kiểm thực tế.
- Khi có nhiều include phụ thuộc, activation từng object có thể không đủ; cần activate cả bộ hoặc dùng SE80/SE38 trong 1 request.

### Ghi source object đã có: `DeployFromFile`/`ImportFromFile` lỗi 423, dùng `SyntaxCheck` + `UpdateObjectAtomic`
**[CONFIRMED]** Trên `GUI_BIDIPHAR_DEV100` (14/10/2026), `DeployFromFile` và `ImportFromFile` (nạp từ file local, tên file `<ten>.prog.abap`) đều fail ở bước ghi với `423 ExceptionResourceInvalidLockHandle: Resource INCLUDE <prog> is not locked`, dù TR Modifiable và đúng owner; lock handle không sống qua các request.
- **Cách ổn định:** `SyntaxCheck(object_url, content)` rồi `UpdateObjectAtomic(object_url, object_name, source, transport)`. Source truyền inline; file ~1300 dòng vẫn chạy (khoảng 28k token mỗi lần gọi, SyntaxCheck và Atomic mỗi cái một lần).
- **`UpdateObjectAtomic` dùng được cho bảng DDIC:** `object_url=/sap/bc/adt/ddic/tables/<ten>` với source DDL `define table ...`; xóa field khỏi bảng 0 dòng activate thành công. `SyntaxCheck` trên URL bảng trả `null` khi sạch.
- **Kiểm chứng sau khi ghi:** `ExportToFile(PROG, <name>, output_dir=<thư mục có sẵn>)` rồi `diff -w --strip-trailing-cr` với file local (file export ra CRLF); rẻ và đáng tin hơn `activation.success`. Trước khi ghi đè, export bản SAP và so với bản local để chắc không có sửa tay trên SAP.
- **`EditSource` chạy được trên host này** (không dính 423, khác `DeployFromFile`/`ImportFromFile`): dùng cho sửa nhiều chỗ nhỏ trên file lớn, chỉ gửi đoạn thay đổi; để `syntax_check=true` và `transport`, mỗi lần gọi tự activate nên thứ tự các bước phải giữ chương trình biên dịch được ở từng bước (bỏ chỗ dùng trước, rồi mới bỏ khai báo). Gọi tuần tự, không gọi song song.
- **Mẹo kiểm tra biên dịch sau khi đổi DDIC:** một `EditSource` sửa comment với `syntax_check=true` buộc SAP kiểm tra cả chương trình với cấu trúc bảng mới.
- **`GetInactiveObjects` rất lớn** (58k ký tự, 2109 dòng trên hệ này): harness tự lưu ra file, dùng `grep` trên file đó thay vì đọc.
- **`GetTableContents` với `sql_query`** đọc được dữ liệu ở client 100 trên host này, không dính `403 CSRF`.

### Giới hạn mạng đã xác nhận
**[CONFIRMED]** `GetConnectionInfo` chỉ cung cấp config tĩnh, không phải xác nhận kết nối.
- `dial tcp ... no such host`/`lookup ... no such host` = mạng/VPN chưa lên.
- `CONNECTION_CLOSED` ngay lúc nạp tool = tiến trình `vsp.exe` khởi động rồi đóng stdio, cần kiểm tra `.mcp.json` / `SAP_PASSWORD`.
- `403 CSRF token validation failed` ở datapreview = kết nối đã tới nhưng POST bị chặn; không phải mạng/VPN.
- `dial tcp ... connectex: A connection attempt failed because the connected party did not properly respond` (timeout) trên `GUI_BIDIPHAR_DEV100` lúc 14:52 ngày 15/10/2026 (trong giờ hành chính) tự hết sau vài phút, gọi lại lần sau chạy bình thường; chỉ cần thử lại 1 lần, không phải lỗi cấu hình.
- **Chọn `--url` khi hostname ICM không với tới (`GUI_APA_DEV_100`, 27/10/2026)**: SMICM/SAP Logon cho hostname + cổng HTTP, nhưng (a) hostname có thể resolve ra IP công cộng không vào được từ máy dev (`Test-NetConnection` fail) trong khi IP nội bộ của SAP Logon (VPN) vào được; (b) cổng HTTP của ICM có thể chỉ trả `307` chuyển sang `https://<hostname>:<cổng HTTPS>/` nên `vsp.exe` treo/timeout. Cách làm: thử `curl.exe -k -I http://<IP>:<cổng HTTP>/sap/public/ping` xem `location`, rồi dùng `--url https://<IP nội bộ>:<cổng HTTPS>/` + `SAP_INSECURE=true` (chứng chỉ cấp cho hostname nên lệch với IP). Kiểm `GET /sap/bc/adt/discovery?sap-client=<client>` có `-u user:pass` trả `200` (không auth trả `401` = ADT bật).
- **[CONFIRMED 27/10/2026, `GUI_APA_DEV_100` (752)] `RunQuery` viết SQL nhiều dòng bị lỗi `Table/View E071 WHERE not found`** (xuống dòng sau tên bảng bị đọc thành một phần tên bảng): viết cả câu SQL trên **một dòng**. Kiểm tra TR không release được: `RunQuery` trên `E071` (đối tượng trong TR), `REPOSRC` (`r3state` A/I của source), `REPOTEXT` (text pool, có cả dòng `r3state='I'`), `DWINACTIV` (danh sách object inactive, cột `OBJECT`/`OBJ_NAME`/`UNAME`) đều đọc được. Lỗi SE09 `Object REPT <include> is inactive` = text pool của include còn bản inactive dù source (`REPS`) đã active; MCP không activate được text pool (endpoint `textelements` 404), phải làm ở SE38/SE80.
- **[CONFIRMED 27/10/2026, `GUI_NKG_DEV_300` (754)] `RunQuery` từ chối hàm SQL trong điều kiện `ON`** (`LEFT( c~awkey, 10 )` → lỗi `"(" is not allowed here. "." is expected`), dù cùng cú pháp (`CONCAT` trong `ON`) vẫn activate được trong code ABAP. Câu SELECT thử bằng `RunQuery` chỉ nên nối bằng cột trần; muốn nối theo `AWKEY` thì chạy 2 câu riêng rồi đối chiếu bằng tay.
- **Binary `vsp.exe` KHÔNG có flag nào cho SAP router string** (xác nhận qua `vsp.exe --help`, 25/09/2026) — toàn bộ flag liên quan kết nối chỉ có `--url`/`--service` (ADT endpoint HTTP/HTTPS), `--user`, `--password`/`--pass`, `--client`, `--browser-auth`, `--saml-auth`, `--cookie-*`, `--credential-cmd`, `--insecure`; không có `--router`/`--saprouter`/tham số nào nhận cú pháp `/H/host/S/port/H/...`. Vì `vsp.exe` kết nối qua giao thức ADT (HTTP/HTTPS tới `--url`), không phải RFC/DIAG cổ điển, nên khái niệm SAP router string (vốn dùng để `saprouter` proxy RFC/DIAG qua firewall) không áp dụng trực tiếp cho binary này. Nếu hệ đích chỉ truy cập được qua saprouter, đường khả thi là dựng 1 kênh mạng khác đứng trước `vsp.exe` (VPN, SSH tunnel, hoặc reverse proxy HTTP) rồi trỏ `--url` vào endpoint cục bộ đó — không phải cấu hình trực tiếp trong `.mcp.json`/tool call.
- **[CONFIRMED] 401 "Logon failed" khi `SAP_PASSWORD` KHÔNG rỗng = sai mật khẩu thật hoặc user bị khoá/hết hạn** (24/09/2026, case `GUI_ACG`) — khác `dial tcp`/`no such host` (mạng) và `CONNECTION_CLOSED` (password rỗng). Tool tự báo "not retrying... risks locking the SAP user" → KHÔNG gọi lại cùng credential, hỏi user xác nhận mật khẩu/trạng thái user trước.
- **[CONFIRMED] `vsp.exe` chế độ MCP server KHÔNG đọc `.vsp.json` / `--system`; `--credential-cmd` chỉ dùng cho SAML** (19.10.2026, đọc mã nguồn `C:\Citek\vibing-steampunk\cmd\vsp\main.go`: `runServer` → `godotenv.Load()` (file `.env` ở thư mục đang chạy, không đè biến đã có) → `resolveConfig` lấy `SAP_URL/SAP_USER/SAP_PASSWORD/SAP_CLIENT` từ cờ dòng lệnh > biến môi trường (viper prefix `SAP_`) > `.env`; `.vsp.json` chỉ do `resolveSystemParams` của lệnh CLI dùng). Triệu chứng khi cấu hình sai: `/mcp` báo **"Connection closed"**, stderr `Error: SAP URL is required` (dùng `--system`) hoặc `Error: authentication required` (dùng `--credential-cmd` cho basic auth). Cấu hình đúng đã test thật (`GetSystemInfo` trên `GUI_S19_DEV100` OK): `env` trong `.mcp.json` có `SAP_URL`/`SAP_USER`/`SAP_CLIENT`, mật khẩu `SAP_PASSWORD` trong `.env` cùng thư mục dự án; nhiều server khác mật khẩu → `"SAP_PASSWORD": "${VSP_<HỆ>_PASSWORD}"` + biến Windows. Lệnh `vsp systems`/`vsp config show` là chế độ CLI — báo `pwd:env ✓` KHÔNG chứng minh MCP chạy được; muốn kiểm phải khởi động server và gửi `initialize` + `tools/call`. `${BIEN}` trong `.mcp.json` chỉ lấy từ biến môi trường hệ điều hành — khai trong `.claude/settings*.json` không có tác dụng (server nhận nguyên chuỗi `${...}` làm mật khẩu → đăng nhập sai). **Repo này chọn**: `SAP_PASSWORD` ghi thẳng trong `env` của `CodeABAP/<KH>/.mcp.json` (gitignore), lên git là `.mcp.json.example` mật khẩu trống — xem `HUONG_DAN_CAU_TRUC.md` mục 2.

### `CreateObjectAtomic` vào `$TMP` bị chặn dù `--allowed-packages` có ghi `$TMP`
**[CONFIRMED]** Trên `GUI_BIDIPHAR_DEV100` (15/10/2026) `CreateObjectAtomic(PROG/P, package_name=$TMP)` trả `operations on package '$TMP' are blocked by safety configuration (allowed: [Z*  $TMP])`.
- **[CONFIRMED]** Nguyên nhân là dấu cách sau dấu phẩy: `"Z*, $TMP"` bị tách thành `"Z*"` và `" $TMP"` (thông báo lỗi in 2 dấu cách giữa `Z*` và `$TMP`). Sửa `SAP_ALLOWED_PACKAGES` thành `"Z*,$TMP"` (không dấu cách) trong `.mcp.json`, nạp lại MCP rồi `CreateObjectAtomic` vào `$TMP` chạy được (15/10/2026). Khi sửa chỉ đổi biến `env` `SAP_ALLOWED_PACKAGES`; dòng `--allowed-packages "Z*, $TMP"` trong `args` vẫn còn dấu cách mà vẫn chạy, nên chưa rõ cái nào được ưu tiên. Các server `GUI_*` khác trong `.mcp.json` còn chuỗi cũ có dấu cách, gặp lỗi tương tự thì sửa giống vậy.
- **[CONFIRMED]** `SyntaxCheck` trên `object_url` của program CHƯA tồn tại trả `null` không có giá trị, vì chưa có object để kiểm tra. Quy trình tạo program mới đã chạy đúng (15/10/2026): `CreateObjectAtomic(PROG/P, $TMP)` với source 1 dòng `REPORT <ten>.` để tạo object, `SyntaxCheck` source đầy đủ trên object đã tồn tại, rồi `UpdateObjectAtomic`.
- **[CONFIRMED]** `SyntaxCheck` trên object đã tồn tại bắt được lỗi thật (thử `TYPE` không tồn tại trả `severity E, Type ... is unknown`), nên kết quả `null` trên object có sẵn đáng tin. Sau khi ghi, `ExportToFile` rồi `diff -w --strip-trailing-cr` với file local cho kết quả giống hệt.

- **[CONFIRMED]** `RunQuery`/`GetTableContents` đọc dữ liệu client 800 chạy tốt (không dính 403 CSRF), nhưng **cấm `MANDT` trong WHERE** (`The client field "MANDT" cannot be specified`; client tự xử lý) và **field list phải đúng tên cột thật** (`DD02T` không có `TABCLASS`, `TKES1` không có `UNAME`: lỗi `Unknown column name ... until runtime, you cannot specify a field list`). - **[CONFIRMED]** `GetStructure` đọc được structure DDIC (kèm annotation `enhancementCategory`) — dùng để biết structure có append được không. `GetSource(PROG)` đọc được program chuẩn (VD `RKDKENNZ`).
- **[CONFIRMED]** `RunQuery` với `WHERE ... OR repid LIKE 'Z%'` trên bảng cấu hình lớn trả rất nhiều dòng (tốn token); luôn lọc theo khóa chính xác (`applclass = 'KKML'`) hoặc dùng `GROUP BY` + `COUNT(*)` để khảo sát trước.

DESCENDING`; kiểm tra bảng rỗng bằng `SELECT COUNT(*)` hoặc `GROUP BY bdatj` trước khi kết luận bảng có dữ liệu (trên APA PRD800: `CKMLKEKO`/`CKMLKEPH` rỗng, dữ liệu cost component split của ML nằm ở `CKMLPRKEKO`/`CKMLPRKEPH`).
