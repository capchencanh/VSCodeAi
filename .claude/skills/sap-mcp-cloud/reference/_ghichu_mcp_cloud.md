## 1. Trạng thái tool đã xác nhận

### Hoạt động tốt

- `SearchObject` — tìm object theo tên/wildcard, trả về URI/type/package. Chỉ nhận `query`/`maxResults`, KHÔNG filter theo object type.
- `GetPackage` — lấy info package. Chỉ nhận `package_name`, KHÔNG có tham số filter field/type — luôn trả full danh sách object kèm rác IAM/system-generated (`SUSH`, `SIA1/2/3/6/7`, `SICF/TYP`, `TOBJ/TOB`, `IWSV/IWVB/IWOM/IWSG`, `OA2S`, `WAPA/WO`, `SMBC/TYP`, `G4BA`, `SCO2`, `UIAD/TYP`...). Muốn gọn lại phải tự lọc JSON trả về theo field `type`, giữ nhóm nghiệp vụ (`DDLS/DF`, `CLAS/OC`, `TABL/DT`, `BDEF/BDO`, `DCLS/DL`, `DDLX/EX`, `SRVD/SRV`, `SRVB/SVB`, `DOMA/DD`...) — không lọc được phía server.
- `GetSource(object_type=DDLS/...)` — đọc full source, cả CDS view chuẩn SAP lẫn custom. Dùng tool này thay cho `GetCDSElementInfo`.
- `GetTransport` / `GetUserTransports` / `ListTransports` — tra cứu TR và TR con (task), trả về đầy đủ objects/tasks.
- `GetConnectionInfo` — kiểm tra session/feature hiện tại (hana, abapgit, rap, amdp, ui5, transport).
- `SyntaxCheck(object_url, content)` — validate cú pháp DDL/ABAP mà KHÔNG cần lock, KHÔNG cần lưu. Luôn dùng để test nháp trước khi ghi.
- `LockObject` / `UnlockObject` — tự thân hoạt động bình thường (trả `lock_handle` hợp lệ, unlock thành công).
- `CreateObject` — tạo object mới (shell) thành công, kể cả DDLS. Với flow tạo+ghi+activate trọn gói, ưu tiên dùng `CreateObjectAtomic` bên dưới thay vì `CreateObject` + `WriteSource` riêng.
- `GetTable(table_name)` — đọc ĐỊNH NGHĨA (cấu trúc field, kiểu, key) của bảng native (TABL/DT), kể cả bảng custom Z không có CDS view nào build trên đó (vd `ZSDA_IG_CUS_LOG`, xác nhận 22/09/2026). Đây là đọc METADATA cấu trúc, KHÔNG phải đọc DATA — không bị chặn bởi giới hạn `S_DEVELOP` của `RunQuery`/`GetTableContents` trên bảng native ở mục "Giới hạn" bên dưới. Dùng tool này để lấy tên field chính xác khi cần viết SQL debug cho 1 bảng native chưa có CDS view.
- **[CONFIRMED 01/10/2026] Muốn đọc nguyên 1 package (hàng chục class/CDS) để phân tích: dùng `GetPackage` lấy danh sách rồi `ExportToFile(object_type, object_name, output_dir)` từng object — file lưu ra đĩa, đọc/grep cục bộ, không tốn context.** `ExportToFile` chạy tốt với `CLAS` (thêm `include=implementations` để lấy `locals_imp` của behavior pool RAP — nếu không chỉ ra file global rất ngắn), `INTF`, `DDLS`, `BDEF`, `SRVD`, `FUGR` (chỉ ra file chính; muốn thân FM dùng `GetFunction(function_name, function_group)`). `GitExport` cả package vẫn lỗi WebSocket 403 (xem mục 6), nên dùng cách này thay thế. `output_dir` phải tồn tại sẵn; dùng đường dẫn 8.3 của scratchpad nếu có dấu cách/ký tự lạ.
- `GetMessageClassTexts` bắt buộc cả 2 tham số `name` và `language` (vd `language=EN`) — thiếu 1 trong 2 báo "name is required"/"language is required" (xác nhận 01/10/2026).
- `RunQuery` đọc giá trị cố định (fixed values) của domain custom qua CDS hệ thống: `SELECT value_low, text FROM DDCDS_CUSTOMER_DOMAIN_VALUE_T( p_domain_name = 'ZEINV_DO_X' )` — cú pháp tham số dùng dấu `=` (dấu `:` của CDS DDL báo lỗi "is not allowed here. = is expected"). Dùng được thay cho việc đọc domain khi `GetTypeInfo` trả 406 (xác nhận 01/10/2026). Lưu ý: custom CDS view `define view entity ... as select from DDCDS_CUSTOMER_DOMAIN_VALUE_T(...)` (kiểu `ZxxxI_STATUS`) cũng `RunQuery` được bình thường.
- `GetPackage` trả mô tả (`description`) của các object **bị lệch dòng** (mô tả của object này nằm ở object kế tiếp, nhất là sau object không có mô tả) — đừng tin cột `description` của `GetPackage`; muốn mô tả đúng dùng `SearchObject(<tên chính xác>)` (xác nhận 01/10/2026, package `ZPK_EINV_HOADON`).
- **[CONFIRMED 09/10/2026] `GetPackage` trên package chứa nhiều proxy SOAP (`SPRX/31`, ví dụ 1 package consume web service VNPT trên `mcp_cus_seadent`) trả >200k ký tự (~5.900 dòng) → tool tự lưu ra file `tool-results`, không in vào chat.** Đừng đọc cả file; `Grep` trực tiếp file đó theo `"type": "CLAS` (kèm `-A 3`) để lấy tên class thật, bỏ qua proxy sinh tự động. Tương tự `GrepObjects` với pattern rộng (`tax|vat`) trả hàng trăm match — thu hẹp pattern hoặc `ExportToFile` class ra đĩa rồi dùng `Grep` cục bộ (mục "Muốn đọc nguyên 1 package" ở trên).

- **[CONFIRMED 09/10/2026] Debug lỗi runtime của 1 package đã có: `GrepPackage(package_name, pattern, object_types='CLAS/OC')` khoanh vùng nhanh 1 từ khoá (vd tên field) khắp các class, trả số dòng + dòng khớp → rồi `ExportToFile` đúng class cần đọc.** `GetRevisions` đòi `type`+`name` (truyền `object_url` báo "type and name are required"); `versionTitle` thường ghi số ticket/ngày — dùng để lần ra thay đổi gần đây gây lỗi (xem mục 11). `I_BillingDocumentText` không tồn tại trên `mcp_ABC_CUS`; `RunQuery` đọc được cả bảng custom (`zeinv_tb_hd`, có `GROUP BY LENGTH(...)`) lẫn CDS custom (`zsd_i_eiv_profile_pf`). **Debug lỗi tích hợp HTTP: tìm bảng log request/response của project (vd class gọi API có method kiểu `save_service_log`) rồi `RunQuery` — xem được payload thật đã gửi + phản hồi, nhanh hơn đặt breakpoint.** `LIKE` chạy được trên cột STRING (body/message), nhưng ký tự `"` trong literal `LIKE` làm `RunQuery` báo "Only one SELECT statement is allowed" (parser coi `"` là comment) — bỏ `"` khỏi pattern.

### Bộ tool `*Atomic` — ưu tiên dùng thay cho Lock+WriteSource/UpdateSource thủ công

Nhóm `WriteSource`/`UpdateSource`/`ImportFromFile`/Lock+UpdateSource thủ công từng bị lỗi HTTP 423 khi ghi/activate. Bộ tool `*Atomic` xử lý dứt điểm:

- `CreateObjectAtomic` — tạo mới + ghi source + activate trong 1 lần gọi.
- `UpdateObjectAtomic` — ghi đè source đã có + activate trong 1 lần gọi.
- Điều kiện bắt buộc: `SyntaxCheck` phải sạch lỗi TRƯỚC khi gọi Atomic (tool không tự sửa cú pháp giúp).
- Lỗi 409 "already locked in request X" → object đang bị khoá ở TR/task khác với `transport` param đang truyền — đổi `transport` sang đúng số X (xem qua thông báo lỗi hoặc `GetTransport`) rồi gọi lại, không phải bug.
- Còn có thêm các tool Atomic chuyên biệt khác (chưa test hết): `CreateDataElementAtomic`, `CreateDomainAtomic`, `CreateStructureAtomic`, `CreateTableAtomic`, `CreateTableTypeAtomic`, `UpdateDataElementAtomic`, `UpdateDomainAtomic`, `DeleteObjectAtomic`, `SetDataElementProperties`, `SetDomainProperties` — ưu tiên dùng khi làm việc với đúng loại object tương ứng.
- `CreateTableAtomic` — **hoạt động tốt** (xác nhận 23/09/2026, case `ZIM_TB_MIGOBUF` package `ZPK_MM_CUSTOMLOGIC_MIGO`), khác hẳn `CreateObjectAtomic` với CLAS (mục 7 dưới đây, lỗi HTTP 500). Các lỗi/giới hạn gặp phải và cách xử lý:
  - `description` > 60 ký tự → lỗi rõ ràng "The description is too long. Maximum length: 60 characters" — rút ngắn lại.
  - Tên bảng > 16 ký tự → lỗi "Select a shorter name for <TÊN>" — khác giới hạn 30 ký tự của CLAS/DDLS (xem bảng naming convention skill `abap-cloud-naming`: Database Table giới hạn 16, không phải 30).
  - Nếu truyền `transport` là **task con** đang bị khoá bởi **TR cha** (case: user đưa số task con, nhưng object bị khoá ở TR cha) → bước ghi source bên trong `CreateTableAtomic` fail với lỗi 409 y hệt mục 8 dưới đây ("already locked in request <TR cha>"), nhưng **shell table đã kịp tạo xong** (chỉ thiếu field). Cách xử lý: KHÔNG gọi lại `CreateTableAtomic` (sẽ báo "Resource ... does already exist" vì shell đã có) — dùng `SyntaxCheck` để validate lại full DDIC source (field đầy đủ), rồi gọi `UpdateObjectAtomic(object_url: "/sap/bc/adt/ddic/tables/<ten_thuong>", object_name, transport: <TR cha>, source)` để ghi tiếp + activate. Lưu ý `object_url` KHÔNG có hậu tố `/source/main` (tool tự thêm) — truyền kèm `/source/main` sẽ bị lỗi 404 "No suitable resource found" do bị nối lặp đường dẫn.
  - Field kiểu quantity (`menge_d` + annotation `@Semantics.quantity.unitOfMeasure`) trên **table DDIC nguồn cổ điển** (`define table ... { }`, không phải CDS view) dễ báo lỗi "Annotation with reference to unit code for field X is missing/uncomplete", và annotation CDS-style `@Semantics.unitOfMeasure: true` trên field đơn vị bị cảnh báo "not a valid annotation and will disappear on save" (annotation này chỉ hợp lệ trên CDS view, không phải table DDIC classic). Cách né đơn giản cho bảng buffer nội bộ (không cần hiển thị UI): dùng kiểu số thuần `abap.dec(n,d)` thay vì data element quantity kèm annotation.

### Đọc source class CLAS — lưu ý cấu trúc include

- `GetSource(object_type=CLAS, include=definitions|implementations|macros)` KHÔNG trả về method của chính class đó — 2 include này chỉ chứa local helper class/type/macro declarations (thường rỗng, chỉ có boilerplate comment). Muốn đọc 1 method cụ thể của class chính → dùng `GetSource(object_type=CLAS, method=<ten_method>)`.
- Muốn tìm kiếm (grep) xuyên suốt TOÀN BỘ class (mọi method gộp chung) mà không vướng giới hạn token của GetSource với class lớn → dùng `GrepObjects(object_urls: ["/sap/bc/adt/oo/classes/<ten_class_lowercase>/source/main"], pattern: ...)`. Endpoint `.../source/main` chứa full source gộp mọi method, trả về đúng dòng khớp + context thay vì cả file nên không bị lỗi vượt token.
- `GetClassInfo` báo lỗi HTTP 403 "No authorization to access .../cai/objectexplorer/objects" trên hệ thống này — không dùng được. Cần metadata class (list method/attribute) thì thử `GetClassComponents(class_url)` thay thế (chưa test).
- `GetObjectStructure` (mọi object type, không chỉ CLAS) cũng gọi cùng endpoint `.../cai/objectexplorer/objects` → cùng lỗi 403 "No authorization" như `GetClassInfo` (xác nhận 22/09/2026, thử với object_type HTTP `ZSD_API_INTEGRATION_CREADIT`) — không dùng được trên hệ thống này.

### Giới hạn/lỗi đã xác nhận (không phải bug cú pháp, là giới hạn thật của tool/authorization)

## 2. Giới hạn cú pháp CDS (không phải bug tool, là rule CDS cần nhớ)

- Mệnh đề `WHERE` không dùng được `field IN (...)` list trong `define view entity` ở hệ thống này → viết chuỗi `OR` thay thế.
- Association ON condition KHÔNG được tham chiếu tới association khác của cùng view (vd `_Delivery.Field` trong ON của association khác) → chỉ dùng `$projection.<field>` đã có trong SELECT list.
- `$projection.<field>` dùng trong ON condition phải là field "thật" (lấy trực tiếp từ source, hoặc field đơn từ 1 association khác) — KHÔNG được là field dẫn xuất qua path expression nhiều cấp (vd `_Vendor._CurrentDefaultAddress.AddressID`). Nếu cần loại field này phải xử lý ở layer khác (native field có sẵn, AMDP, custom entity...).
- ABAP SQL (trong class): `FOR ALL ENTRIES` KHÔNG cho phép CASE/SQL expression trong SELECT list — lỗi activate "The addition CASE is not allowed in combination with FOR ALL ENTRIES" (gặp 17/07/2026 ở `ZIM_CL_PNK_VENDOR`). Cách xử lý: SELECT field thô rồi ghép/tính bằng ABAP sau (`COND` + `condense`), hoặc bỏ FAE chuyển sang `WHERE ... IN` range.
- CDS: KHÔNG được dùng `CASE` trực tiếp trong mệnh đề `ON` của JOIN (`left outer join X on ... = case when ... end`) — lỗi syntax "Unexpected keyword 'case'" (gặp 23/07/2026 ở `ZIM_I_SupplierProfile`). CASE vẫn dùng bình thường trong SELECT list, chỉ riêng trong ON của JOIN là không được.
- CDS: CŨNG KHÔNG được dùng sub-select lồng trong `FROM` (derived table kiểu `select from ( select from X {...} ) as _header`) — lỗi syntax "Unexpected keyword 'select'". CDS (cả `define view` và `define view entity`) không hỗ trợ derived table trong FROM như native SQL. Muốn tính field gộp trước khi JOIN thì phải tạo 1 CDS view thật riêng (object DB khác) rồi SELECT FROM view đó — không lồng inline được.
- Hệ quả: khi JOIN ra fan-out nhiều dòng cho cùng 1 key do `ON` dùng `OR` giữa 2 điều kiện độc lập (vd `Supplier = BP OR Customer = BP`, cả 2 field đều khác initial và trỏ tới 2 BP khác nhau → khớp cả 2 dòng riêng biệt), cách xử lý AN TOÀN (không cần CASE, không cần sub-select) là giữ nguyên cấu trúc `OR` nhưng thêm điều kiện `is initial`/`is not initial` để 2 nhánh loại trừ lẫn nhau theo đúng thứ tự ưu tiên mong muốn:
  ```
  left outer join I_BusinessPartner as BusParner on
    (
      _header.Customer     is not initial
      and _header.Customer = BusParner.BusinessPartner
    )
    or
    (
      _header.Customer     is initial
      and _header.Supplier is not initial
      and _header.Supplier = BusParner.BusinessPartner
    )
  ```
  Ưu tiên cách này hơn CASE-trong-ON hay sub-select-trong-FROM vì chỉ dùng đúng các toán tử (`is initial`/`is not initial`/`and`/`or`/`=`) vốn đã hợp lệ trong ON của CDS.

## 3. Kinh nghiệm thiết kế CDS

- **Chained lookup (join nhiều cấp phụ thuộc nhau) khi có GROUP BY**: khai báo `association` riêng cho từng bước sẽ LUÔN lỗi "association X cannot be used locally in the view" nếu ON condition của association sau tham chiếu field của association trước (CDS không cho phép association tham chiếu association khác trong ON, kể cả gián tiếp qua GROUP BY). Cách đúng: dùng JOIN trực tiếp trong FROM (`select from A left outer join B on ... left outer join C on ...`) — B/C có thể tham chiếu lẫn nhau bình thường như SQL chuẩn. Quy tắc chung: lookup ĐỘC LẬP → dùng `association`; lookup PHỤ THUỘC NHAU theo chuỗi (A→B→C) → JOIN trong FROM clause. Ví dụ đã áp dụng thành công trong `ZIM_I_PNK`: `I_MaterialDocumentItem_2 as Item left outer join I_OutboundDeliveryItem as Delivery on ... left outer join I_SalesOrder as SO on Delivery.ReferenceSDDocument = SO.SalesOrder` — lấy được `SO.SalesOrderType` qua 2 bước join.
- **Released API vs internal API**: view có annotation `@VDM.lifecycle.contract.type: #SAP_INTERNAL_API` (vd `I_BusinessPartnerAddressTP_2`) KHÔNG được dùng trong ABAP Cloud custom dev (SyntaxCheck báo "The use of CDS Entity X is not permitted"). Chỉ dùng view `#PUBLIC_LOCAL_API` (kiểm tra qua annotation trong `GetSource`, hoặc `GetAPIReleaseState`).
- **Projection view không dùng làm base object được**: view released dạng projection (`as projection on X`, vd `I_BusinessPartnerAddressTP_3`) KHÔNG thể dùng làm base object trong FROM/JOIN hay target của 1 `association` từ interface view thường (lỗi "Projection Views are not allowed as base object for this entity type") — chỉ tham chiếu hợp lệ từ projection view khác cùng kiến trúc RAP Business Object. Nếu field cần lấy chỉ tồn tại qua projection view released (không có view interface tương đương) và không muốn dựng nguyên RAP BO chỉ để lấy 1-2 field, đây là giới hạn kiến trúc thật — đành để field đó placeholder rỗng.
- **Custom field In-App Extensibility** (tiền tố `YY1_`) không hiện trong `GetSource`/DDL gốc (chèn transparent lúc runtime) nhưng vẫn query được qua `RunQuery`/`SELECT` bình thường. Muốn xác minh field có tồn tại: thử `RunQuery(SELECT <field> FROM <view>, max_rows: 1)` thay vì tin `GetSource`.
- **Composition + to-parent (parent-child chuẩn RAP)**: pattern tham khảo `ZIM_PK_BBGH_PXK` (`ZIM_I_BBGH_HEADER`/`ZIM_I_BBGH_ITEM`) dùng `define root view entity` + `composition [x..*] of <item> as _Item` (header) + `association to parent <header> as _Header` (item) — KHÔNG cần Behavior Definition cho mục đích facet UI / OData $expand read-only. Nếu dùng `as projection on X` + `redirected to composition child/parent` ở tầng projection (C_ layer): 2 view phải activate ĐỒNG THỜI (compiler check chéo lẫn nhau) — `UpdateObjectAtomic` từng object một sẽ luôn lỗi 409/E dù thử thứ tự nào (không có cách atomically active 2 object cùng lúc qua tool này). Cách né: KHÔNG dùng `as projection on`/`redirected to`, khai báo composition/to-parent MỚI trực tiếp trên `as select from X as Y` ở cả 2 tầng (I_ và C_, mỗi tầng tự có composition/to-parent riêng, không kế thừa/redirect) — activate tuần tự bình thường, chỉ warning (đã test thành công với `ZIM_I_PNK`/`ZIM_I_PNK_ITM`/`ZIM_C_PNK`/`ZIM_C_PNK_ITM`). Lưu ý: field key phải khớp CHÍNH XÁC giữa các tầng — field là key ở tầng C_ thì PHẢI là key ở tầng I_ nó select from, nếu có composition/to-parent liên quan tới key đó.
- **Trước khi tự join Business Partner Address lấy địa chỉ/tên đầy đủ NCC** (dễ vướng released-API/projection-view ở 2 mục trên): luôn `SearchObject`/`GrepPackage` tìm xem package hiện tại đã có sẵn 1 CDS view custom nào join sẵn Supplier+Address chưa (thường có field kiểu `FullAddress`/`...FullName`) — tái dùng thay vì tự dựng lại từ đầu. - **Lũy kế (cumulative/running total) qua self-join `<=`**: nếu bảng nguồn CHỈ có dòng cho kỳ "có phát sinh" (vd bảng giao hàng chỉ có dòng khi thực sự giao), mà không có dòng cho kỳ "0 phát sinh", thì view lũy kế dựng theo pattern `select from X as a inner join X as b on b.key<=a.key group by... sum(b.qty)` sẽ THIẾU hẳn các kỳ 0 phát sinh — không phải sai giá trị mà là MẤT LUÔN DÒNG của kỳ đó. Khi 1 view khác `left outer join` theo đúng kỳ vào view lũy kế này, kỳ bị thiếu sẽ NULL → `coalesce(...,0)` làm lũy kế bị "reset về 0" thay vì giữ nguyên trị từ kỳ có phát sinh gần nhất trước đó → mọi số lũy kế/còn lại tính SAI từ đó trở đi (thổi phồng, thiếu phần đã trừ). Cách sửa: đổi FROM của view "theo kỳ" (`ZSD_I_DELIV_PER_PERIOD`) sang bắt đầu từ bảng KỲ (`zsd_tb_slkhtt`) rồi `left outer join` sang bảng phát sinh, kèm `coalesce(<qty>, cast(0 as abap.quan(13,3)))` bên trong `sum(...)` — đảm bảo MỌI kỳ đều có 1 dòng (kể cả 0). Quy tắc chung: view lũy kế theo kỳ luôn phải dựng trên "bảng kỳ" (spine table) làm FROM chính, KHÔNG bao giờ dựng trên bảng phát sinh (transaction table) làm FROM chính rồi join ngược ra bảng kỳ.

## 5. Giới hạn cú pháp ABAP OO (CLASS — không phải bug tool, là rule ABAP Cloud cần nhớ)

- **`CONVERSION_EXIT_ALPHA_INPUT`/`_OUTPUT` (và FM cổ điển nói chung) bị chặn trên ABAP Cloud**: `SyntaxCheck` báo lỗi thẳng "The use of Function Module CONVERSION_EXIT_ALPHA_INPUT is not permitted." Thay thế bằng string template format option (được release cho Cloud): pad số 0 bên trái dùng `|{ lv_input WIDTH = 18 ALIGN = RIGHT PAD = '0' }|` (ví dụ convert product/material code ngắn '25000028' → '000000000025000028' 18 ký tự trước khi filter OData `Product eq '...'`). Lưu ý khác: `ALPHA = IN/OUT` trong string template (`|{ dobj ALPHA = IN }|`) chỉ pad đúng khi `dobj` là 1 biến ĐÃ có type/length cố định khớp đích cần — dùng trực tiếp trên 1 literal (`'25000028' ALPHA = IN`) sẽ KHÔNG pad gì cả (literal tự lấy length của chính nó = 8, không biết đích cần 18) → âm thầm gửi sai key cho OData filter, trả về 0 dòng dù data có thật (dễ nhầm là "hết data" hoặc "lỗi kết nối"). Dùng `WIDTH/ALIGN/PAD` để chủ động chỉ định độ dài đích, an toàn hơn `ALPHA` trong trường hợp này.

- **Tên method/attribute tối đa 30 ký tự** (giới hạn identifier chuẩn ABAP). Gặp 12/08/2026 khi activate `ZEINV_CL_HOADON_ITEM`: đặt tên method `APPLY_UNIT_CONVERSION_FOR_GROUP` (31 ký tự) → báo lỗi "longer than the allowed 30 characters". Trước khi đặt tên method/attribute mới, đếm ký tự, rút ngắn nếu cần (vd đổi thành `APPLY_UNIT_CONV_FOR_GROUP` = 25 ký tự).
- **Trong `CLASS ... IMPLEMENTATION.` ... `ENDCLASS.`, KHÔNG được có comment đứng độc lập ở cấp top-level nằm NGOÀI khối `METHOD ... ENDMETHOD`** (vd 1 dòng comment đặt giữa `ENDMETHOD.` của method này và `METHOD` của method kế tiếp, hoặc giữa `ENDMETHOD.` cuối và `ENDCLASS.`). Activate báo lỗi message `OO_SOURCE_BASED012`: *"The class contains unknown comments which can't be stored... You wrote a comment outside a method implementation or you commented a whole method implementation."* Gặp 12/08/2026 khi thêm method mới `APPLY_UNIT_CONV_FOR_GROUP` vào `ZEINV_CL_HOADON_ITEM` — đặt marker `"#<ID> • [CS]_<User> - Add Start/End - <date>"` ngay trước `METHOD` và ngay sau `ENDMETHOD.` (ngoài thân method) → lỗi. Cách sửa: mọi marker/comment đánh dấu code mới trong IMPLEMENTATION section PHẢI đặt **bên trong** thân method — ngay sau dòng `METHOD xxx.` và ngay trước dòng `ENDMETHOD.` — không đặt xen giữa các method. Riêng CLASS DEFINITION section (PUBLIC/PROTECTED/PRIVATE SECTION, giữa các khai báo DATA/TYPES/METHODS) không bị giới hạn này, comment đặt tự do như ABAP thường.
- **`WITH PRIVILEGED ACCESS` KHÔNG được kết hợp cùng `INNER JOIN` (hay JOIN bất kỳ) trong cùng 1 FROM clause** — lỗi grammar ngay tại từ khoá `WITH` (xác nhận 24/09/2026 qua Eclipse ADT của user, case `ZSD_CL_SALESFLOW_QRY_MANAGE` package `ZPK_SD_ZSD01`: viết `FROM zsd_i_tb_tier1 AS t WITH PRIVILEGED ACCESS INNER JOIN @lt_soi AS soi ON ...` để bypass DCL `#MANDATORY` của `ZSD_I_TB_TIER1`/`ZSD_I_TB_TIER2` → lỗi cú pháp thật, không phải do đặt sai vị trí `WITH` so với `AS`). Cách né: bỏ hẳn JOIN, chỉ SELECT đơn giản `FROM <cds_view> WITH PRIVILEGED ACCESS` (không alias, không JOIN — đúng dạng đã confirm sạch ở mục 7 dưới, case `if_oo_adt_classrun`). Nếu logic gốc cần lọc theo 1 tập dữ liệu khác (tương đương JOIN cũ), chuyển lọc đó sang ABAP thuần (LOOP/FILTER/range) SAU khi SELECT WITH PRIVILEGED ACCESS xong, không lồng JOIN vào cùng câu SELECT đó.

## 12. Giới hạn cú pháp Open SQL khi viết SELECT thủ công cho file `.sql` (chạy qua Data Preview/SQL console — KHÁC với CDS DDL ở mục 2)

Áp dụng khi viết 1 câu `SELECT` thô (không phải `define view entity`) để lưu vào file `.sql` cho user tự chạy (rule tạo file xem `CLAUDE.md`). 3 lỗi xác nhận 17/09/2026 (case đối chiếu `sotiencanchi`, package `ZPK_FI_ZAP12H`), người dùng tự chạy qua console SQL trong VSCode và trả kết quả về:

- **KHÔNG dùng kiểu CDS built-in có dấu chấm** (`abap.dec(23,2)`, `abap.curr(...)`, `abap.char(...)`) bên trong `CAST(... AS ...)` của câu SELECT thô — console SQL parse nhầm dấu `.` giữa `ABAP` và tên kiểu thành dấu kết thúc câu lệnh → lỗi `"Only one SELECT statement is allowed"` dù thực tế chỉ có 1 SELECT. Cách né: nếu 2 field so sánh đã cùng kiểu số/CURR thì bỏ hẳn CAST (so sánh thẳng); chỉ cast khi thật cần và dùng tên kiểu không có dấu chấm.
- **So sánh field CHAR/kiểu ký tự cố định độ dài với "rỗng" phải dùng `' '`** (đúng 1 ký tự trắng) — dùng `''` (chuỗi 0 ký tự) sẽ lỗi `"The empty character literal cannot be used in database expressions. Use a literal that contains precisely one blank character."`. Áp dụng cho mọi so sánh dạng `field = ''`/`field <> ''` với field abap_boolean, CHAR, LCHR... (vd `is_del = ' '`, `ClearingJournalEntry = ' '`).
- **Nhân field CURR/DEC với `-1` có thể vượt giới hạn 31 chữ số của HANA** (lỗi `"The maximum possible number of places... no more than 31 places"`) vì DB suy luận kiểu kết quả phép NHÂN rộng hơn phép cộng/trừ/âm đơn. Cách né: dùng dấu âm đơn `( - field )` thay vì `field * -1`.
- **Alias/tên bảng nối với field LUÔN dùng dấu `~` (vd `main~AccountingDocument`), KHÔNG dùng dấu `.`** — dấu `.` (`main.AccountingDocument`) là cú pháp CDS DDL (`define view entity`, xem mục 2), còn SELECT thô cho `.sql`/Data Preview console là Open SQL cổ điển, bắt buộc `~`.
